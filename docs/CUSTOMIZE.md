# 定制指南 · Customize

把这份工作台改成你自己的。全部改动都在 `index.html` 一个文件里，用任意文本编辑器即可。

> 💡 快捷方式：如果只是想改内容而不想碰代码，可以直接在页面上编辑数据，然后点「导出备份」。
> 但页面内编辑不会改到代码里的种子数据 —— 清空浏览器数据后会回到出厂状态。**长期使用请改代码里的种子。**

---

|---|---|---|
| `<title>` | `AI 转型作战台 · Career Ops Workspace` | 你的标题 |

## 2. 改 21 天计划（`STAGES`）

```js
const STAGES = [
  {
    key:  'S1 筑基',              // 唯一键：targets[].stage / resources[].stage 都靠它对上
    name: 'S1 · 筑基（服务）',      // 展示名
    days: 'D1–D5',                // 天数标签
    range:'5 天',
    color:'#2C6E9B',              // 阶段色（同时用于看板进度条与画布节点）
    goal: '打通「服务」：能自己写接口、能自己打包部署',   // 一句话目标
    focus:'FastAPI + Docker + Redis',                  // 关键词浓缩
    tasks:[ '...', '...' ]                             // 关键动作清单
  },
  ...
];
```

**改阶段的注意事项**

- `key` 是关联键。改了 `key`，必须同步改 `targets[].stage` 和 `resources[].stage` 里对应的值，否则分组会散。
- 阶段数不限，但超过 6 个后计划页会变长，建议合并。
- `color` 建议用有区分度的中性色，避免与语义色（红=逾期、绿=完成）语义冲突。

### 改起算日

```js
const START_DATE = '2026-09-15';   // 计划起算日
```

`SPRINT_SEED()` 里的 `D(n)` 和计划轴的「第几天」都基于这个日期推算。
**首次打开时基于它计算相对日期**；已落盘的数据不会自动前移，需要清空数据或手动改 `due`。

## 3. 换学习资料库（`RES_SEED`）

```js
function RES_SEED(){
  return [
    {
      id:    'r1',
      stage: 'S1 筑基',          // 必须对应 STAGES[].key
      pri:   'P0',              // P0 必学 / P1 应该学 / P2 了解层
      kind:  'B站',             // B站 | GitHub | 文档
      type:  '视频',            // 视频 | 仓库 | 规范
      title: '...',
      by:    '...',             // 作者或检索关键词
      url:   'https://...',
      why:   '...',             // ★ 为什么给这个人推荐（最重要）
      hours: '10–12h',
      done:  false
    },
    ...
  ];
}
```

### 选材原则（沿用原设计）

1. **围绕真缺口选材，不做泛学习** —— 与 `jdmap` 里的 `red` 项一一对应
2. **`why` 必须挂钩已有经验** —— 例如「你的 docx 解析经验能直接迁移到 RAG 文档解析」
3. **标注时间成本**，并允许「学不完直接跳过」的 P2 项
4. **优先能产出可展示成果的资料** —— 能 push 成公开仓库的，优于纯理论

`kind: 'B站'` 的 `url` 建议用搜索链接（`https://search.bilibili.com/all?keyword=...`），
因为具体视频会失效，而搜索词长期有效。

## 4. 换投递冲刺清单（`SPRINT_SEED`）

```js
function SPRINT_SEED(){
  const D = n => dateAdd(START_DATE, n-1);   // D1 = 起算日当天
  return [
    {
      id:   'sp1',
      day:  'D1',
      due:  D(1),
      out:  '简历事实核对表',        // ★ 当天产出物（这天结束手里有什么）
      title:'把所有量化数字核实一遍，一个都不许含混',
      items:[ '...', '...' ],      // 子项
      hours:'2h',
      risk: '别在这一步反复纠结措辞',  // 这一天的坑
      done: false
    },
    ...
  ];
}
```

### 强度设计建议

- **一天一个产出物**，且必须是「能拿给人看」的实体（表格 / 仓库 / 录屏 / 定稿文档）
- **中间插一天缓冲**（原设计是 D7）—— 计划必然落后 1–2 天，缓冲不是浪费，是防止「落空即放弃」
- **最后一天硬性收口**（原设计是 D14：定稿 + 首批投递 10 家）
  不要留「准备好再投」的开放式结尾

天数不限于 14。改长改短只需调整数组长度，页面会自动显示进度环。

## 5. 换 JD 关键词映射（`JDMAP_SEED`）

```js
{ id:'j1', kw:'Python 开发', freq:'必备',
  resume:'考勤数据治理流水线 / docx 标准化引擎',   // '—' 表示暂无弹药
  ready:'green',                                  // green | blue | red
  note:'措辞用「独立编写数据处理脚本」…' }
```

**填法**：去招聘网站抓 10–20 条目标岗位 JD，把重复出现的关键词提取出来，逐条填三段：

| 字段 | 填什么 |
|---|---|
| `kw` | JD 里的原词，别改写 |
| `freq` | 出现频次：`核心` > `必备` > `高频` > `加分` |
| `resume` | 你的哪段经历能对上；`—` 表示没有 |
| `ready` | 能不能讲清细节：能=`green`，要练=`blue`，没有=`red` |
| `note` | 补法 + 面试时怎么讲（含该避讳的措辞） |

**校验一致性**：所有 `ready:'red'` 的条目，都应该能在 `STAGES` 或 `SPRINT_SEED` 里找到对应的补法。
找不到就说明计划漏了，或者这个词条其实不该标红。

## 6. 换认知协议（`COGNITION`）

```js
const COGNITION = [
  {t:'注意力是脉冲式的，不是线性的', k:'所以你需要的不是「每天 8 小时」，而是 3–4 个 45 分钟的强专注块。'},
  ...
];
// t = 现象（一句话描述你的真实特征）
// k = 含义与做法（这个特征意味着该怎么设计工作方式）
```

**写法要求**：
- `t` 要具体到可验证，避免「有点拖延」这类空话
- `k` 必须落到**可执行的结构**上（改计划粒度、改反馈方式、改启动门槛），而不是「要更自律」

如果你不想保留这个模块，把 `VIEWS` 里 `profile` 那一整项删掉即可，该视图会从导航消失。

## 7. 换配色

配色由 CSS 变量驱动，主题无关的变量在 `:root`，主题相关的在 `body[data-theme="dark"]` / `body[data-theme="light"]`。

```css
body[data-theme="dark"]{
  --bg:#0A0C10;      /* 页面底 */
  --card:#12161B;    /* 卡片 */
  --card-2:#171C23;  /* 卡片内区块 */
  --ink:#E9EDF3;     /* 主文字 */
  --ink-2:#98A3B3;   /* 次文字 */
  --ink-3:#687385;   /* 弱文字 */
  --line:#232A33;    /* 边框 */
  --acc:#2DD4BF;     /* ★ 唯一强调色 */
  --bad:#F87171; --warn:#FBBF24; --ok:#4ADE80; --info:#60A5FA;
  /* 画布专用 */
  --cv-dot:rgba(255,255,255,.055); --cv-edge:#3A434F;
  --cv-leaf:#171C23; --cv-leaf-ink:#AEBBCC; --cv-hint:rgba(18,22,27,.92);
}
```

**改色要点**

1. **`--acc` 只保留一个**。多强调色 = 没有强调色，会直接破坏「一屏一焦点」的设计意图。
2. **暗 ↔ 亮必须成对改**。只改一边会导致另一个主题下文字看不清。
3. **画布节点色是另一套**。`--cv-*` 独立于 UI 色，因为 SVG 描边/填充需要按主题切换。
4. **画布调色板**在 JS 里，两套数组同时改：
   ```js
   const PALETTE    = ['#993C1D','#2C6E9B','#2F855A','#6B46C1','#B7791F','#0E7490'];  // 亮色
   const PALETTE_DK = ['#F07C5A','#63A9E8','#5FCB8C','#A78BFA','#E0B24C','#3EC6D8'];  // 暗色
   ```
   同序号是同一个语义槽位。暗色版要整体**提亮**，否则深底上会看不清。

**默认主题**：`<body data-theme="dark">` 是初始值；用户切换后会写入本地并在下次打开时恢复。

## 8. 增删模块

### 删一个模块

1. 从 `VIEWS` 数组删掉该项（导航与移动端 Tab 会自动同步）
2. 从 `refreshAll()` 的 `if/else` 链删掉对应分支
3. `renderXxx()` 函数可保留（不调用即无副作用）
4. 如需同时移除数据，从 `DEFAULT_DATA` 删字段（注意迁移逻辑不要报错）

### 加一个模块

见 [`DATA-MODEL.md` 第 6 节](DATA-MODEL.md#6-扩展点) 的 7 步。

> ⚠️ **别一次加太多。** 视图数量超过 8 个后，导航开始需要分组折叠，移动端 Tab 也要横向滚动。
> 建议：先加一个、用一周、确认真的在用，再加下一个。

## 10. 部署

产物只有一个 HTML，随便挂哪儿都行：

| 方式 | 命令 / 操作 |
|---|---|
| **GitHub Pages** | Settings → Pages → Source 选 `main` / `root` → 访问 `https://<user>.github.io/<repo>/` |
| **Cloudflare Pages** | 连仓库，构建命令留空，输出目录填 `/` |
| **Netlify / Vercel** | 拖拽整个目录上传，或连仓库 |
| **任意静态服务器 / 对象存储** | 上传 `index.html`，或整站丢进 Nginx 根目录 |

> 部署前请确认：**没有把真实隐私数据写进代码里的种子数据**。
> 部署后的链接是公开可访问的，任何人拿到都能打开（数据仍只在他自己的浏览器里）。

按 [`ARCHITECTURE.md` 第 9 节](ARCHITECTURE.md#9-自检清单) 的 10 条走一遍。最低限度：

- [ ] 打开页面无控制台报错
- [ ] 8 个视图逐个切换都正常渲染
- [ ] 暗 ↔ 亮主题切换后画布、表格、按钮都跟随变化
- [ ] 一键生成思维导图 / 流程图，节点不重叠、文字不截断
- [ ] 手机窄屏（或浏览器缩到 375px 宽）无横向溢出
- [ ] 清空数据后刷新，种子数据能重新填充
- [ ] 导出 JSON → 清空 → 导入，数据完整回来
