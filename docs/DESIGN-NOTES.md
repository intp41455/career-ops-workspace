# 设计说明 · Design Notes

记录这套界面为什么这么长，以及为了达到它放弃了什么。

---

## 1. 目标读者决定了设计

这份工作台最初是为一个具体的人设计的：**ADHD 倾向 + INTP 认知风格**、正在经历职业转型、需要同时管理 21 天学习计划、14 天投递冲刺和一堆待补的技术缺口。

这类使用者的核心困难不是「不会安排」，而是：

| 真实困难 | 常规待办 App 的做法 | 为什么不管用 |
|---|---|---|
| 启动阻力大于执行难度 | 给一个长列表 | 列表本身就是决策负担，打开就焦虑 |
| 注意力是脉冲式的 | 按小时排日程 | 脉冲式注意力无法被日程表约束 |
| 需要即时反馈才有动力 | 进度百分比 | 「已完成 3/12」不构成完成感 |
| 讨厌重复劳动 | 要求每日打卡 | 打卡本身变成新的重复劳动 |
| 完美主义伪装成「准备不足」 | 鼓励「准备好了再开始」 | 直接强化拖延 |

于是设计的核心命题变成：

> **不是让人更自律，而是让系统承担更多判断。**

## 2. 五条设计取向

### 2.1 一屏一焦点

首屏顶部是「**唯一焦点条**」：只显示**现在该做的那一件事**。

```
如果你的清单里同时有逾期项和今日项 → 焦点条显示逾期项，并转为警示色
处理完 → 焦点自动上移到下一条
```

配合看板四栏里专门设的「**卡住了**」列 —— 允许显式承认卡点，而不是让任务在「进行中」里慢慢腐烂。

**代价**：首屏信息密度低，习惯一次性总览的人会觉得「太空」。
**取舍理由**：对目标读者而言，减少决策点比增加信息量更有价值。

### 2.2 低装饰噪音

- 去掉渐变、去掉重投影、去掉无信息量的装饰性图形
- 卡片用细描边 + 极轻投影区分层级，而不是靠颜色堆叠
- 单一强调色 `--acc`，**只用于标注「现在该做什么」**，不作装饰

**代价**：视觉冲击力弱，第一眼不够「炫」。
**取舍理由**：视觉噪音会持续消耗注意力，而视觉冲击只在第一次打开时有效。

### 2.3 等宽数字

所有进度、计数、日期使用 `--mono` 等宽字体。

**理由**：数字跳动会分散注意。等宽保证「从 9 到 10」时布局不抖，阅读时能快速对齐数量级。

### 2.4 动词化的条目

计划与待办全部写成**可执行动词**，而非学习主题：

| ❌ 不好 | ✅ 好 |
|---|---|
| 学习 FastAPI | 跑通文件上传接口，并 push 成公开仓库 |
| 学习 RAG | 产出分块对比实验结果表 |
| 准备面试 | 准备 3 个「踩坑—定位—解决」的故事 |

**理由**：面对 INTP 型使用者，「学习 XXX」的边界是开放的 → 永远可以再学一点 → 永不开始。
而「跑通一个接口」有明确终点 → 能启动、能完成、能有反馈。

### 2.5 外部结构替代意志力

- 四栏看板 = 外部前额叶，把「这件事现在处于什么状态」的判断交出去
- 唯一刷新入口 = 状态变化只有一条路径，不需要记「我刚才改了什么」
- 明确标注 P0/P1/P2 = 允许跳过 P2 而不产生负罪感

## 3. 视觉系统

### 暗色优先

默认暗色。理由不是「好看」，而是：

- 长时间阅读时对比更柔和，减少疲劳
- 亮色作为可选主题保留给白天 / 打印 / 投屏场景

两套主题的**语义色保持同序**（红=逾期、黄=注意、绿=完成、蓝=中性提示、紫=分类），只调整明度与饱和度。

### 画布配色是独立的

画布（无限画布 / 思维导图）的配色单独成组，不共用 UI 色：

| 变量 | 作用 |
|---|---|
| `--cv-dot` | 背景网点 |
| `--cv-edge` | 连线与箭头 |
| `--cv-leaf` / `--cv-leaf-ink` | 叶子节点底色与文字 |
| `--cv-hint` | 左下角状态条 |
| `--cv-shadow` | 节点投影色 |

**原因**：SVG 需要按主题切换描边与填充，且导出 SVG 时要内联成具体色值 —— 不能依赖 CSS 类继承。

调色板（`PALETTE` / `PALETTE_DK`）同理分两套，同序号是同一语义槽位。暗色版整体提亮，
否则深底上的深色节点会「糊」在背景里。

## 4. 中文排版的三个具体决策

### 4.1 宽度按实测算，不按字符数

早期实现用 `len(text) * 13.5` 估宽，对中文严重低估（中文视觉宽度 ≈ 2× 拉丁字符）。
结果：节点文字大量溢出卡片。

现在用 `cvTextW()` 逐字符累加：

```js
CJK 区间按 size 计，拉丁按 size * 0.55 计
覆盖范围：0x1100-0x115F / 0x2E80-0xA4CF / 0xAC00-0xD7A3 /
          0xF900-0xFAFF / 0xFE30-0xFE4F / 0xFF00-0xFF60 / 0xFFE0-0xFFE6
```

并据此**自动折行**而非截断 —— 折行保留信息，截断制造歧义。

### 4.2 输入框字号 ≥16px

低于 16px 时，iOS Safari 会在聚焦时自动放大整个页面。
这一条不是审美选择，是硬约束。

### 4.3 窄屏表格转卡片

JD 映射是一张四列表格，窄屏下横向滚动体验很差。
用 `td[data-l]::before { content: attr(data-l) }` 让每个单元格在窄屏下自带字段名，表格变成一组卡片：

```css
@media(max-width:760px){
  .tbl thead{display:none}
  .tbl tr{border:1px solid var(--line); border-radius:var(--r-s); margin-bottom:8px}
  .tbl td[data-l]::before{content:attr(data-l); display:block; font-size:9.5px; color:var(--ink-3)}
}
```

## 5. 交互上的四个克制

| 不做 | 原因 |
|---|---|
| **不做浏览器通知 / 系统推送** | 需要 Service Worker 与权限，与「双击即用、零依赖」冲突。「今日要处理」置顶区已等价于提醒 |
| **不做账号体系** | 90% 场景是单人使用。用 JSON 导出 / 导入迁移，比注册登录轻得多 |
| **不做管理后台** | 使用者既是管理员也是用户，同页设置抽屉足够 |
| **不做视频 / 大文件存储** | 超出工作台范畴；图片场景另有压缩到 800px + base64 的方案 |

另外画布上的「一键生成」刻意只给三个入口（阶段导图 / 求职流程 / 由计划生成全图），
而不是开放一个「选择图表类型」的长表单 —— **减少选择 = 降低启动阻力**。

## 6. 沿用自原始设计的几条硬约束

这几条来自真实踩坑，写进代码注释里当护栏：

1. **全内联零外链**
   来源：AI 生成的页面常引用外部 CDN，用户只保存了 HTML → 库 404 → 功能全废。
   现在图标、图表、字体全部内联或使用系统字体栈。

2. **调用链必须是 DAG**
   来源：两个渲染函数互相调用 → 栈溢出。语法正确、静态检查抓不到、只在运行时崩。
   现在所有刷新走唯一的 `refreshAll()`。

3. **首屏非空**
   来源：首次打开是空白页，是用户判定「不好用」的第一原因。
   现在预置示例数据，且**故意包含 1 条逾期项** —— 让使用者第一眼就看到「系统在帮我盯着什么」。

4. **布局算法必须单向分层**
   来源：早期拓扑分层沿边反向遍历，把根节点推到第 3 层，造成 17 组节点压叠。
   现在用单向 Kahn 拓扑排序 + 按父节点分列。

5. **缩放设下限**
   来源：大图自动适配时缩到 25%，完全不可读。
   现在宁可变溢出滚动，也不缩到看不清。

## 7. 已知的取舍与不足

诚实地列出这套设计做不到的事：

| 不足 | 说明 |
|---|---|
| **不改行为** | 界面能降低启动阻力，但不能替代执行。计划表本身不会让人变自律 |
| **首屏信息密度低** | 「一屏一焦点」对需要总览的人是负优化 |
| **无云端同步** | 换设备需手动导出 / 导入；清浏览器数据会丢 |
| **单用户** | 无协作、无分享、无评论 |
| **画布导出格式有限** | 仅 SVG / PNG，不支持 XMind / OPML 等专有格式 |
| **数据内容无法自证** | 工作台只保证「表述结构可讲」，不替代使用者对量化数字的事实核对 |
| **无自动化测试** | 目前只有语法检查与控制台自测片段；主因是单文件无构建链，引入测试框架会破坏零依赖约束 |
